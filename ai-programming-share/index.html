Context Loop

把“对话”还原成请求循环

每一轮看似连续，底层其实是 messages 数组的持续增长。context window 是上限，轮次越多，token 成本越高。

messages 持续增长context window 是上限token 消耗随轮次增加
messages = [
    {
        "role": "system",
        "content": self.render_system_prompt(react_system_prompt_template)
    },
    {
        "role": "user",
        "content": f"<question>{user_input}</question>"
    }
]

while True:
    # 请求模型
    content = self.call_model(messages)

    # 处理 content
    # 等待用户输入，或调用工具产生新的输入
    # 产生新的请求数据 new_msg

    messages.append({
        "role": "user",
        "content": new_msg
    })

Act III · BSH Skill & Limits
11 / 19

把经验固化成 Skill

让 AI 正确写 BSH

01

语法约束

BeanShell 接近 Java，但有细微限制，需要明确写入生成规则。

02

运行上下文

AI 需要知道哪些对象、类、方法可用，以及如何读取返回值。

03

安全边界

通过 bsh-script-development 告诉 AI 如何正确编写 BSH 脚本。

Skill 的价值不是“魔法”，而是把人的经验写成机器可遵守的流程。

BeanShell 的限制

不使用泛型模板参数

写 List list = new ArrayList();
不要写 List<Long>、Map<K,V>。

不使用动态参数格式化

避免 String.format("%d", value) 这类写法。

不使用 lambda

用匿名接口类或普通循环替代。

不使用注解

不要写 @Override 等 @ 注解。

Act III · Boundary
12 / 19

许愿式编程

适合什么，不适合什么

适合

  • 工具类代码
  • 一次性脚本
  • 排查辅助
  • BSH 调试脚本
  • 数据迁移 / 数据修复脚本

不适合

  • 直接许愿生成生产核心代码
  • 没有 review 的线上逻辑
  • 权限不清晰的自动执行
  • 无日志、无回滚、无验证的修改

生产代码不能许愿；但调试脚本、一次性脚本、BSH 非常适合 AI 辅助。

Vibe Coding is a tool, not an exemption from engineering discipline
